# Code Ownership Map

> **Owner:** SRE Agent platform team.
> **Purpose:** one table that tells a new engineer, for any capability, exactly which file to
> open, which Terraform resource provisions it, which config controls it, which test (if any)
> proves it works, where its logs land, and who owns troubleshooting it in production.
> **Source of truth:** every citation below was re-opened and confirmed against the live repo
> during this pass (2026-08-09). Status labels (implemented/verified/planned) are not repeated
> here — see the [Implemented vs Planned Matrix](../management/implemented-vs-planned-matrix.md)
> for that; this page is about *where the code lives*, not whether it's proven.

## Notes on "none" / "n/a" cells

- **Agent Identity** and **Agent Gateway** have no "Main Code" cell because they are pure GCP
  platform constructs provisioned by Terraform — there is no application-level Python that
  implements them, only Terraform that configures them and application code that relies on the
  identity/gateway existing.
- **Metrics** has no "Main Code" cell because the 11 log-based metrics are Terraform-defined
  filters over log fields that application code (rows above) already emits — there's no separate
  metrics-computation code to point at.
- **Deployment / CI-CD** has no "Main Code" cell because it's entirely workflow YAML + Terraform,
  not Python the agent runs at investigation time.
- Every "no test" claim above was grep-confirmed against `tests/` (and `iac/agent/tests`,
  `mcp/tests` where relevant) during this pass — not assumed. See the
  [Implemented vs Planned Matrix](../management/implemented-vs-planned-matrix.md) for the
  authoritative status label on each of these gaps.
